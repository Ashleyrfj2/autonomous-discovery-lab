# Retrieval integration evidence — 2026-11-03

Crossref's official [REST API documentation](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) specifies the public `api.crossref.org` JSON metadata service, `/works` search, DOI/title/publication metadata and no sign-up requirement. The adapter records original response content and extracted per-publication metadata separately. Metadata titles are prior-art candidates; they cannot establish a paper's experimental findings.

Live acceptance used the application fetcher to retrieve two publication records for run-length encoding and the [RFC 1951 primary document](https://www.rfc-editor.org/rfc/rfc1951.txt). The application preserved raw SHA-256 content, extracted text, retrieval timestamps, URLs, IDs and an exact source quote. See phase-5-live-retrieval.json, phase-5-evidence-snapshot.json and the selected public artifact archive under docs/phase_reports/artifacts/phase-5. A second CLI research-and-resume run retrieved three records and completed the technical loop, with novelty unknown and no live inference calls.

Network policy is explicit opt-in, HTTPS only, exact allowed hosts, no credential URLs, public-only resolved addresses, numeric address pinning with TLS hostname verification, separately validated redirects, bounded bodies, absolute request interruption and bounded DNS waits. No environment proxy or credential header is inherited. Retrieved text remains untrusted data, never authority to change tools, security or spending. Conflict extraction reports candidates for investigation, not proven contradictions; source statements require exact matching quotes; model interpretations retain an unverified label.
