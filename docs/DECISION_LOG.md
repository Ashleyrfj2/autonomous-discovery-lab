## DEC-014 — 2026-11-03 — Bound caller latency, retain uncertain remote spending
Problem: per-operation HTTP timeouts do not ensure a caller deadline, and cancellation cannot prove the server stopped. Selected: bounded daemon transport threads (eight per process), absolute caller deadline and trusted cancellation context; cooperative rate-backoff waits. Before-wire failures known to be zero cost can release their reservation; ambiguous/late outcomes retain it and are not silently replayed. Canceled inference pauses for reconciliation and never triggers fallback; pure-worker interruption retains resumable state without a scientific failure. Each callback binds its stage version. Evidence: provider deadline/cancel/backoff tests, full bounded-operation checks. References: [HTTPX timeout semantics](https://www.python-httpx.org/advanced/timeouts/), [Python subprocess lifecycle](https://docs.python.org/3.12/library/subprocess.html). Tradeoffs: transport threads can outlive the caller; no remote cancellation/billing guarantee, and provider software limits rely on accurate rates. Affected: models, security/cancellation,budget, lab. Revisit with provider-native request reconciliation/idempotency; never equate local timeout with zero cost.
