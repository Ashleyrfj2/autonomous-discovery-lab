## DEC-007 — 2026-11-03 — Verified local trusted-worker confinement
Problem: the fixed reviewed Python worker needs network/filesystem/resource restrictions. Alternatives: arbitrary Docker execution (insufficient), remote sandbox (not configured), native local defense in depth for allowlisted code. Selected: macOS deny-default Seatbelt with exact interpreter/worker/system-code read permissions, OS CPU/file limits, no inherited secrets, bounded numeric fixtures, Python audit denial, and mandatory parent wall/RSS/output monitoring. Initial startup aborted because the system dynamic-loader rules were missing; inspecting `/System/Library/Sandbox/Profiles/dyld-support.sb` identified required bootstrap operations, so that specific system profile is imported. Unrestricted reads/network were not added. Native adversarial probe verifies file/network denial. Darwin rejected DATA/AS rlimits even outside confinement; RSS monitoring enforces the configured limit with a sampling-overshoot limitation. [Apple DTS](https://developer.apple.com/forums/thread/661939) and the local sandbox-exec manual state that custom profiles are private/deprecated. Tradeoff: current macOS-only backend, no claim of arbitrary-code or production sandbox safety; unsupported systems fail closed. Affected: experiments/security. Revisit with a supported isolated-worker service or VM; preserve the reviewed-code allowlist and explicit authorization.
