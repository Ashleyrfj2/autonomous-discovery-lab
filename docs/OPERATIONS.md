# Operations

Run from the `autonomous-discovery-lab` repository. Install Python 3.12 and `uv sync --locked`. Development defaults to mocked inference, no secrets required. Local checks: `uv run ruff check .`, `uv run pyright`, `uv run pytest -q`, `uv build`. CLI and runtime operations will be documented as implemented. Do not assume commands from the plan already exist.

Default limits: per run USD 2; daily USD 10; experiment 120 seconds; retries 2; hypotheses 5; concurrency 1. These are software limits, not provider hard caps. Raising authority or spending requires explicit configuration and user authorization. Avoid provider calls during infrastructure tests.

Recovery: read AGENTS and its ordered documents, inspect Git, examine checkpoints/logs/artifacts, run relevant checks, reconcile discrepancies, resume the exact next task from HANDOFF. Checkpoint before refactors/session ends and after tasks/failures/decisions. Export anchors independently for stronger tamper detection. Logs and runtime databases are ignored by Git. Preserve selected sanitized test evidence under docs/phase_reports.

Minimum loop: `uv run autodiscover --root runtime/demo demo`. It produces run ID, report and content-addressed artifacts. `status [RUN_ID]` inspects persisted state; `resume RUN_ID` continues active work; `pause RUN_ID`, `unpause RUN_ID`, and `cancel RUN_ID` control runs. `demo --stop-after 7` leaves committed execution ready for verification, allowing recovery inspection. `integrity --anchor SNAPSHOT.json` verifies against a separately retained snapshot; `snapshot DESTINATION.json` refuses overwrite. Retain snapshots outside the mutable runtime directory. Live inference remains opt-in and no provider is contacted by the default demo. If the repository moves, `uv sync --locked --reinstall` repairs script shebangs.

Research: `uv run autodiscover --root runtime/research research 'run length encoding' --allow-network` retrieves up to three publication records, then stops after RESEARCH for inspection. `resume RUN_ID` completes that run with actual retrieved source IDs in hypothesis provenance. Default demos remain offline. Metadata coverage is bounded and novelty stays unknown. The source catalog also supports reviewed primary-document ingestion, quote-backed claims, knowledge search and explicit/cascading invalidation. Changed content at a previously recorded URL invalidates dependent claims. Selected public local-acceptance artifacts are retained in docs/phase_reports/artifacts; runtime user data remains ignored by Git.

Bounded branching: `uv run autodiscover --root runtime/explore explore` exercises multiple reviewed directions and evidence-driven revision. `demo --algorithm identity` demonstrates a failed baseline followed by an independently evaluated child. `tree RUN_ID` shows lineage, per-candidate results, resource allocations and stopping reasons. `candidate-add RUN_ID FILE.json` imports a schema-checked candidate; `experiment_family: theoretical` records a cross-domain quantitative proposal without granting execution authority. Search settings persist per run and cannot be silently reset. Replicas and renewed experiment allocations use preregistered seeds. Default resource limits remain unchanged; requests now have a smaller software cost allocation across retries/fallbacks to preserve other candidates' budget.

Commercial evidence: follow COMMERCIAL_VALIDATION.md. `market-show OPPORTUNITY_ID` recomputes current level. Profiles and supplied documents do not count as validated demand by themselves. `market-review` requires interactive human confirmation; the lab/model cannot auto-approve it. No buyer outreach, messages, purchases or payments occur through these commands. Local positive gate tests use fixtures; the actual demo remains level 0.

## Phase 8 — bounded local execution and recovery

Create an offline queued task with `uv run autodiscover --root runtime/work enqueue --topic 'bounded local research'`. Run `uv run autodiscover --root runtime/work workers --max-steps 100 --max-seconds 60 --concurrency 2`. Inspect `queue`, `jobs [RUN_ID]`, `status [RUN_ID]` and `tree RUN_ID` using the same root. The default experiment ceiling remains one even with two stage workers. Deliberately configured higher experiment limits require each active/requesting policy to permit admission; the limit applies within this SQLite database, not across independent roots. No service or automatic restart is installed.

SIGINT/SIGTERM requests graceful stop. A worker still running trusted computation is killed/reaped and marked ABANDONED; its completed sibling replicas remain cached. The queue stays resumable. Use `pause RUN_ID`, `unpause RUN_ID` and `cancel RUN_ID` for durable run controls; canceled runs cannot resume. Reinvoke `workers` or `resume RUN_ID` after interruption. Local dead coordinator identities are detected by PID plus creation time; legacy/unrecognized identities wait for lease expiry. Reconciliation terminates only matching workers, rechecks current lease/fence under the write lock, records the reason and retries only bounded pure computation. Permission/cleanup failures fail closed. Never delete jobs or rewrite plans to force retries.

Unknown inference outcomes keep conservative reservations. `status` usage distinguishes settled, reserved and uncertain USD; `charged_usd` is the conservative budget total, not proof of a provider invoice. Caller timeout or cancellation may leave a remote request running. A paused inference-reconciliation run must be investigated against reservation/provider records before any new authorized research attempt; there is no automatic unsafe reset/replay command. Raising a budget or changing a request key does not establish that an earlier charge disappeared. Rate-backoff cancellation cannot initiate a new retry. Do not use production credentials for qualification.

Resource status includes persisted worker identity, attempts/errors, raw result digest, elapsed time and observed RSS in artifacts. Queue attempt counters include contention; workflow committed-stage counts are authoritative for scientific progress. Scheduling `max_seconds` stops admission and signals cancellation, then drains cleanup. SQLite writer waits, retrieval timeouts and OS child cleanup can extend return time; no hard deadline for an unresponsive kernel or remote provider is promised. RSS polling can briefly overshoot; fixed trusted workers remain the only execution backend.

Reproduce acceptance with new unused paths:

```sh
uv run python scripts/qualify_phase8.py --root runtime/phase8-repeat --output docs/phase_reports/phase-8-repeat
```

The script runs Ruff, Pyright, the full suite, build and focused tests; restarts a coordinator across eight offline workflows; independently recomputes 24 jobs; records concurrency and budget observations; exports a no-overwrite snapshot and hashes/archives all known mock artifacts. It refuses existing directories and checks source identity before/after. This is a short bounded mock-provider qualification. Review `acceptance.json`, `validation.json`, `source-manifest.json`, `targeted-tests.xml`, `bounded-operation.json` and snapshot/CAS before acceptance. Keep runtime operator data and credentials out of Git. Historical Phase 8 records remain preserved; final accepted evidence is `phase_reports/phase-8-acceptance/`.

## Phase 9 local operator API (dashboard not yet implemented)

`uv run autodiscover --root runtime/demo serve --port 8765` starts a foreground loopback-only API against an existing current-schema root. An interactive terminal prompts for a temporary operator passphrase (12–200 characters); it is never printed or persisted. No service is installed and no experiment or paid call starts. Stop with Ctrl-C. The browser dashboard is not available yet. API consumers log in using same-origin JSON POST /api/session, then receive an HttpOnly same-site cookie; GET /api/session returns the current CSRF value for authenticated stateful requests, including POST /api/session/logout. Use the exact http://127.0.0.1:8765 origin/Host and loopback peer. Do not put passphrases/session values in URLs, shell history, reports or logs. Sessions rotate on login, expire after8 hours and disappear on process exit. Login is rate-limited to five attempts per minute. Root/report data and GETs remain read-only.

Authenticated GETs expose /api/runs, /api/runs/{id}, /tree, /jobs, /stages, /evidence and /usage under the run path, plus /api/queue. Pages accept limit1–100, offset and optional at_cursor; a changed snapshot requires refresh. Unexpected/integrity errors return generic codes. Budget changes, arbitrary filesystem paths, provider execution and live-inference authorization are not exposed.

Workflow controls: authenticated POST /api/runs/{id}/control requires same Origin, session cookie and X-CSRF-Token, action pause/resume/cancel, expected_version, expected_fence and request_id UUID. Cancel also requires confirm_run_id matching the path. Stale/reused commands return409; identical retries return their original receipt with replayed=true and do not apply again. Always refresh current state after a receipt. Resume only changes eligibility; invoke existing bounded workers separately.

Market review: GET /api/market/{opportunity}/review returns current classification, source-bound evidence context and confirmation text. POST to the same path requires explicit operator confirmation, evidence_id, HumanReview, expected_cursor and request_id UUID, with session/Origin/CSRF. The server derives human authority; it never accepts client roles. A different source digest/cursor or invalid source is rejected; an identical request returns the original review ID. The response separately recomputes current assessment. Synthetic demand cannot be promoted. CLI remains available. These contracts are backend-qualified; a browser approval UI is not yet implemented, and no actual buyer/payment has been validated.
