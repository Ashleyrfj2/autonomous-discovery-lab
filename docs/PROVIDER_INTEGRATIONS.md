# Provider integration evidence — checked 2026-11-03

Official Meta [API reference](https://dev.meta.ai/docs/api-reference) documents `https://api.meta.ai/v1`, bearer auth and `/chat/completions`. The [chat schemas](https://dev.meta.ai/docs/api-reference/chat-completions/schemas) document completion token caps, structured response formats and token usage. The adapter uses `max_completion_tokens`, validates returned content/usage, and rejects truncated/refused output. Models and task-specific capabilities require explicit configuration; legacy Llama API is not assumed interchangeable.

Official Baseten [Model APIs overview](https://docs.baseten.co/inference/model-apis/overview) and [chat reference](https://docs.baseten.co/reference/inference-api/chat-completions) document the inference origin, bearer auth and compatible message/usage envelopes. This implementation targets Model APIs, not arbitrary custom deployments. It uses `max_tokens`; structured capability must be configured for the selected model.

No specific model, context window, price or rate limit is shipped as a live default. Model catalog health probes establish availability only. Provide current model/pricing/capability sources, verification date, environment variable name, and explicit authorization. Credentials are read only on authorized adapter use. HTTP tests inject mock transports and fake credentials; no real endpoint or billing was exercised.

Reservations use conservative full configured context input cost plus output cap cost. This relies on accurate provider limits/prices, is intentionally pessimistic, and is not a provider-enforced cap. Ambiguous consumption keeps the reservation; crashes never release it automatically. Actual overruns are recorded and pause the run. Cost dates use UTC request day. Cached completed results avoid repeat calls; incomplete request identity needs explicit reconciliation. A failure may fall back only along a preconfigured route with a task-specific evaluation reference; selection identity and comparison evidence are persisted. No claim of model-family equivalence follows from a common HTTP shape.
